Using ProceedGate with n8n

Place an HTTP Request node immediately before expensive or sensitive nodes (OpenAI, HTTP Tool, SerpAPI, CRM, etc.). Route with an IF node on the check result.

Verified API fields for POST /v1/check: agent_id, task_hash, optional action (tool_call · model_call · retry · …), optional step_hash. See Docs. Fields like workflow_id or reason_code in examples below are illustrative n8n patterns unless marked otherwise.

HTTP Request node (production payload)

POST https://governor.proceedgate.dev/v1/check
Authorization: Bearer pg_ws_...
Content-Type: application/json

{
  "agent_id": "n8n-lead-enrich",
  "task_hash": "sha256-of-lead-id-or-stable-input",
  "action": "tool_call"
}

IF routing (illustrative)

Map the JSON body — production uses allowed and HTTP status (429 when blocked):

// IF node (example expressions)
{{ $json.allowed === true }}  → continue to OpenAI / SerpAPI / CRM
{{ $json.allowed === false }} → stop branch, Slack alert, dead-letter

// Optional: treat zone === "gray" as manual review (Planned workflow guard fields)

Example flow

Webhook → ProceedGate check → IF allowed → SerpAPI → Firecrawl → OpenAI → CRM. On block, skip paid nodes.
